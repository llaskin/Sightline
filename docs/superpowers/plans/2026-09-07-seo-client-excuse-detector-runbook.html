SEO Client Excuse Detector — Release 1 Test Runbook

Operator and human validation the automated suite cannot cover. 385 automated tests already pass; this page is the other gate.

0 / 0 · 0%
Context: everything here runs locally against your own PostgreSQL. Nothing is deployed and nothing leaves the machine. Release 1 needs no Google credentials and no AI provider key; if any step seems to want one, that is a bug worth reporting. The app listens on http://localhost:3100 and PostgreSQL on 5433, chosen so they cannot collide with the crawlseo stack already using 3000 and 5432.
What the automated tests already prove, so you need not re-check by hand: the arithmetic and every threshold boundary, tenant isolation across all API families, idempotency under parallel commits, retention cutoffs, CSV rejection rules, axe accessibility scans, and five responsive viewports. See docs/verification.md. Your job here is the things only a person can judge: does it read honestly, does the wizard feel usable, and does the operator tooling work on a machine that is not mine.

⚠️ STOP AND REPORT if any of these happen

  • Any screen shows a percentage describing how likely the complaint is to be right (for example "82% not valid"). There must be none anywhere.
  • A metric card draws a small trend line (sparkline). There is only ever one value per period, so a shape would be invented.
  • A missing value renders as 0 rather than "Not provided".
  • The app claims leads reached the client when only analytics data was supplied.
  • Anything you typed disappears after a failed save.
  • A sidebar item leads to an error, a blank page, or "coming soon".

Nothing here is irreversible except Step 8. To reset the whole thing: docker compose down -v destroys the database and you start again from Step 1.
